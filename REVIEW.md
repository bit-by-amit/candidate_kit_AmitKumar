# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-38) | Naive timezone replacement and incorrect grace boundary logic. `punch_in.replace()` mixes UTC/local time with IST shift time. `minutes > 10` fails strictly > 10:00 (e.g. 09:40:01 evaluates to 10 min floor, returning 0 instead of 10). Also ignores overnight shifts. | Input: punch-in at `09:40:01` for shift `09:30` returned 0 instead of 10. Also overnight punch-ins past midnight failed. | Replaced with IST-aware datetime calculation, checking `punch_in_ist > shift_start_ist + 10m`, and returning whole minutes elapsed from shift start. |
| 2 | `compute_work_hours` (lines 40-42) | Built-in `round(..., 2)` uses Banker's Rounding (round half to even), violating Rule R4 which strictly mandates arithmetic half-up rounding. | Input: duration yielding 4.545 hours rounded to 4.54 instead of 4.55. | Used `decimal.Decimal.quantize(..., rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44-48) | Missing Rule R3 30-minute minimum threshold, and fails overnight shifts where `shift_end` falls on `date + 1`. | Input: punching out 25 minutes after shift end returned 25 instead of 0; overnight punch-out returned massive negative/zero minutes. | Added overnight calendar day shift for `shift_end_date` and enforced `ot_minutes >= 30` condition (returning 0 otherwise). |
| 4 | `health` (lines 72-75) | Returns hardcoded `{"status": "ok"}` without pinging the database. Contract specifies returning 200 only if MongoDB answers a ping, otherwise 503. | Stopping MongoDB still resulted in `/health` returning HTTP 200. | Added `client.admin.command('ping')` inside a try/except block returning 503 on failure. |
| 5 | `create_employee` (lines 77-85) | Check-then-insert race condition (`find_one` followed by `insert_one`), lack of validation that `shift_start != shift_end`, and `created_at` stored as naive datetime returning non-epoch milliseconds. | Concurrent identical POST requests created duplicate records; equal shift start/end allowed; response failed epoch ms validation. | Added validation `shift_start != shift_end` (HTTP 422), relied on MongoDB unique index on `emp_code` catching `DuplicateKeyError` (HTTP 409), and serialized `created_at` as epoch ms. |
| 6 | `list_employees` (lines 89-96) | Off-by-one pagination (`skip = page * page_size`), total count ignoring department filter, missing ascending sort on `emp_code`, and unformatted `created_at`. | Querying `page=1` skipped the first 20 records; total count reflected entire collection rather than filtered department. | Fixed `skip = (page - 1) * page_size`, updated `count_documents(q)`, added `.sort("emp_code", 1)`, and mapped `created_at` to epoch ms. |
| 7 | `punch_in` (lines 100-122) | Missing 404 for unknown employee; naive datetime without second-truncation (R1); fails overnight date assignment; check-then-insert race condition; injects forbidden `"id"` field into response. | Punching in with nonexistent `emp_code` caused 500 error (`TypeError`); duplicate concurrent punch-ins created duplicate docs; overnight punch-in before shift end assigned to wrong date. | Verified employee exists (404), truncated instants to whole seconds (R1), implemented R1 overnight shift date shift, relied on compound unique index `(emp_code, date)` catching `DuplicateKeyError` (409), and formatted response strictly matching `AttendanceRecord` schema. |
| 8 | `list_attendance` (lines 124-150) | In-memory pagination and sorting (`list(db.attendance_logs.find(q))`), missing secondary sort by `emp_code` ascending, no `date_from > date_to` validation (422), forbidden `"id"` field injected, and raw datetimes returned instead of epoch ms. | Memory exhaustion and high latency on large datasets (100k docs); `date_from > date_to` returned 200 instead of 422; schema validation failed due to injected `id`. | Validated date range returning 422; pushed sorting and pagination directly into MongoDB query cursor; removed `id`; formatted datetimes as epoch ms. |
| 9 | Lifecycle (startup) | Starter lacked automatic index creation, requiring manual intervention and failing explain plan checks. | Database operations performed full collection scans (`COLLSCAN`). | Implemented FastAPI `lifespan` handler to idempotently create all unique and compound indexes at startup. |

### Things Examined and Decided Were NOT Defects
- **Default Shift Times**: In `EmployeeIn`, `shift_start = "09:30"` and `shift_end = "18:30"` match the standard enterprise defaults specified in the OpenAPI contract.
- **Natural Key Addressing**: Addressing attendance records by `(emp_code, date)` rather than an ObjectId in URLs was verified as intentional and correct per `DATA_MODEL.md`.
